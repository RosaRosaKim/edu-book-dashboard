# 밥카(법인카드) 기능 스펙

## 1. 데이터 구조

### 사용자카드정보 시트
| 열 | 필드 | 비고 |
|----|------|------|
| A | 녹스ID | |
| B | 카드번호 | 전체 번호 저장 |
| C | 별칭 | 사용자 지정 (선택) |
| D | 한도 | 비밥카 카드: 사용자 입력 |
| E | 밥카여부 | Y/N, 카드당 1개만 Y |

- 웹페이지관리(ADMIN) 시트에는 카드 정보 저장하지 않음

### localStorage 캐시
- 밥카 식별 완료 여부 저장 → 이후 진입 시 감지 과정 스킵
- 밥카 카드 지정 변경 시 캐시도 갱신

## 2. 최초 진입 플로우

```
밥카 탭 진입
  → 사용자카드정보 시트에 녹스ID 존재?
    → YES: 정상 로드
    → NO: 초기 등록 시작
      ① "카드 등록 중..." → Bizplay에서 카드 목록 조회 → 시트에 저장
      ② "밥카 카드 감지 중..." → 한달전 내역에서 TRAN_KIND_NM에 "중식대" 포함된 CARD_NO 탐색
        → 감지 1개: 자동으로 E열 Y 설정
        → 감지 2개+: 사용자가 하나만 선택
        → 감지 0개: 카드 목록 보여주고 사용자가 직접 선택
      ③ 카드 1개인 경우: 무조건 E열 Y 자동 설정 (감지 과정 스킵)
      ④ localStorage에 식별 완료 캐싱
```

## 3. 카드번호 표시 형식
- 마스킹 규칙: 앞4 + ******** + 뒤4 (예: `4336********0725`)
- 카드명: 항상 마스킹 카드번호만 표시
- 밥카: accent 색상 뱃지로 구분
- 비밥카 + 별칭 있음: 회색톤 뱃지로 별칭 표시
- 별칭 없음: 뱃지 없음

## 4. 카드 수에 따른 UI 분기

| | 카드 1개 | 카드 2개 이상 |
|---|---------|-------------|
| 카드 선택 UI | 없음 | 상단 카드 전환 드롭다운 |
| 기본 표시 카드 | 유일한 카드 | 항상 밥카 카드 |

## 5. 카드 전환 드롭다운 (2개 이상 시)
- 카드 목록 표시 및 전환
- 설정: 별칭 변경, 한도 변경, 밥카 카드 지정 변경 (바텀시트/오버레이 팝업)
- 밥카 선택 시: "밥카 카드 변경"만 표시
- 비밥카 선택 시: "별칭 변경" + "한도 변경" + "밥카 카드 변경"
- 새로고침: Bizplay에서 카드 목록 재조회 (기존 카드의 별칭/한도/밥카여부 유지, 새 카드만 추가)

## 6. 카드 종류별 기능 차이

| 기능 | 밥카 카드 | 비밥카 카드 |
|------|-----------|-------------|
| 한도 | 기존 로직 | 사용자 직접 입력 |
| 잔액/사용량 | 남은잔액 | 한도 있음→잔액 / 없음→누적사용금액 |
| 한도 초기화 | 매월 15일 리셋 | 매월 15일 리셋 |
| 자동결재모드 | 표시 | 숨김 |
| 밥카결재 | 표시 | 숨김 |
| TOP5 | "나의 TOP5" | "TOP5" (해당 카드만) |
| 맛집평가 | 표시 | 표시 |
| Flow 알람 설명 | 전체 알림 | 평일 잔액 알림 |

- 맛집평가는 카드 구분 없이 사용자 전체 통합 데이터

## 7. Flow 알람
- 사용자 단위 ON/OFF (카드별 아님)
- 모든 등록된 카드 대상, 평일에만 발송
- 여러 카드를 **하나의 메시지로 합산** 발송
- 한도 있는 카드: 잔액 표시 / 한도 없는 카드: 사용금액 표시
- 카드명: 밥카→`밥카`, 별칭 있음→`별칭(뒤4자리)`, 별칭 없음→`카드(뒤4자리)`
- 메시지 예: `밥카: 잔액 50,000원 | 팀카드(0725): 사용 120,000원`

## 8. 결재 로직
- 자동결재/밥카결재는 **밥카 카드에서만** 동작
- 카드 2개+ 사용자: 밥카 카드만 결재 대상
- 결재 제목: `{월}월중식대({카드뒤4자리})` — 예: "3월중식대(0725)"
- 상세: [card-approval.md](card-approval.md)

| seq | SEQ | |
| address | MEST_ADDR_1 + MEST_ADDR_2 | 공백 결합 |
